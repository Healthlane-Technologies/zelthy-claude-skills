## Approach — Per-page edit, test after each (Approach B)

The `.jsx` doc pages are the input to `scripts/generate-reference.js`. The extractor only reads four literals:

- `title="..."`, `badge="..."`
- `<Section title="...">` titles
- `props={[{ name, type, default, description }, ...]}` arrays
- `code={` ... `}` blocks with optional `language="..."`

All edits are confined to those literals. Prose JSX is not extracted and is left alone unless visibly wrong.

### Per-page cycle

1. **Read** the `.jsx` page.
2. **Cross-check** against real package source under `/Users/ravi/Downloads/Repos/zango-react-stack/pkg-zango-crud/crud/frontend/src/`. When claims differ, trust the source.
3. **Edit** the page: fix wrong `props={[...]}` entries, add missing ones, update `code={...}` blocks, add missing `<Section>` blocks.
4. **Regenerate**: `bun scripts/generate-reference.js`.
5. **Diff guard**: `git diff skills/zango-frontend/references/` should only touch the reference file(s) for this page's category. Any cross-file churn is investigated before commit.
6. **Browser verify**: open the docs website at the page's route, via chrome-devtools-mcp (fallback: playwright). Pass criteria:
   - Page loads, networkidle reached.
   - Console has no `error` / `warn` tied to the page.
   - Title renders.
   - Props table row count matches the new `props={[...]}` length.
   - Code blocks render with Prism highlighting.
   - Interactive playgrounds (where present) render without runtime crash.
7. **Commit**: one commit per page + its regenerated reference delta. Subject: `docs(<reference>): <PageName> — fix/add ...`.
8. **Stop condition**: if a real-package field is claimed in no source (not types, not hooks, not mocks), stop and ask — don't invent.

### Dev server

- `cd frontend && bun install` once if `node_modules` missing.
- `bun run dev` once, background process, port recorded.
- Server stays up across all 16 page cycles.

### Commit boundary rules

- Never batch multiple pages into one commit.
- Never commit a `.jsx` change without the regenerated reference file.
- Never commit when the diff guard flags unexpected cross-file churn.

## Risks

- **Docs website runtime errors** if a `.jsx` edit breaks a component render (e.g. unclosed tag in a `code={...}` block). Mitigated by per-page browser verification before commit.
- **Extractor ambiguity**: generator parses `props={[{ name: '...', type: '...' }, ...]}` with regex; nested braces or special characters inside `description` strings can cause parse oddities. Mitigation: keep descriptions plain, inspect regenerated reference after each run.
- **Real-package change after 1.0.13-rc.8**: package may advance during the work. Mitigation: single-session execution; pin checks to commit SHA captured at plan start.
- **Browser tool availability**: chrome-devtools-mcp may not be configured on this machine. Fallback plan: use `playwright` skill (already listed as available) to drive headless Chrome.
